# PunchLoader 未来模组与扩展方向

本文记录后续可能开发的正式模组及基础能力。当前仅作为构想与范围备忘，不代表已经排期或开始实现。

## 1. Boss Rush

制作连续 Boss 挑战模式：

- 连续挑战游戏内 Boss。
- 设计战斗间恢复、奖励或更换部件的流程。
- 提供计时、死亡次数、难度和通关结果。
- 后续可加入随机顺序、固定种子和特殊规则。

## 2. 内容解锁器

解锁游戏包体中存在但正常流程无法获得的内容：

- 隐藏但实际可用的颜色。
- 未正式实装、但代码或资源中已有对应 Material 的颜色。
- Boss 专属装备。
- 其他存在于资源、代码或数据中，但没有正常获取入口的内容。

实施前应区分“完整可用内容”“半成品内容”和“仅残留资源”，避免直接开放会导致存档、渲染或玩法异常的项目。

## 3. 真正的自定义地图与战役

现有“自定义地图”本质上只是自定义对战场地，并沿用 Battle 模式规则，存在以下限制：

- 部分场景碰撞或爆炸事件被禁用。
- 没有敌人、Boss、NPC 和对话流程。
- 没有检查点、出口与关卡完成条件。
- 没有冒险模式掉落和奖励。
- 无法将多个地图串联为自定义战役。

目标是建立真正的冒险关卡扩展体系，包括：

- 自定义敌人、Boss、NPC 和对话。
- 检查点、出生点、出口和完成条件。
- 冒险模式掉落、奖励与商店。
- 场景事件、机关、碰撞和脚本触发器。
- 多关卡顺序、分支和自定义战役清单。
- 可供地图作者使用的格式、验证器和开发文档。

## 4. 联网对战

为游戏增加真正的网络多人对战能力：

- 创建或加入房间。
- 同步玩家移动、攻击、技能、伤害和状态。
- 同步地图、回合、比分和胜负结果。
- 处理延迟、断线重连、版本与模组一致性检查。
- 后续考虑大厅、观战和自定义规则。

这是高复杂度方向，需要先调查现有本地多人架构、物理模拟和输入系统。

## 5. 新增部件与颜色

扩展可收集和可装备内容：

### 新颜色

- 新增 Material 与颜色条目。
- 接入颜色仓库、掉落或解锁条件。
- 处理名称、预览、存档与多人显示。

颜色扩展预计比新部件简单，可优先作为内容扩展 API 的试验项目。

### 新部件

- 新模型、材质、图标、名称和说明。
- 部件类型、属性、技能与装备槽规则。
- 掉落、商店、收藏、存档和网络同步。
- 为第三方作者提供注册 API 和示例模组。

## 6. 简体中文普适适配 API

将简体中文模组从“仅汉化原游戏”扩展为其他模组可复用的中文渲染基础设施：

- 将字库扩充到覆盖常用简体中文字、常见标点和必要符号。
- 在简体中文模组中提供稳定的公开 API。
- 外部模组检测到简体中文模组启用后，可注册自己的中文文本。
- 根据既有规则自动选择中文字体、字号、基线、字距和混排方式。
- 保留外部模组原有英文、数字与 ASCII 标点字体。
- 支持菜单大字、菜单小字、Visitor 正文等既有字体类别。
- 提供文本预检，报告字库缺字、文本溢出和不合理换行。
- 明确 API 版本，避免简体中文模组升级后破坏第三方模组。

建议未来提供类似以下能力：

```csharp
ChineseLocalizationApi.RegisterText(modId, originalText, translatedText);
ChineseLocalizationApi.ApplyProfile(textMesh, ChineseFontProfile.MenuLarge);
ChineseLocalizationApi.ValidateText(translatedText, ChineseFontProfile.VisitorBody);
```

实际 API 名称和签名应在架构设计阶段确定。

# LocalizationDebug

> 当前名称沿用既有部署与配置 ID。随着工具范围已经超出汉化检查，后续可单独迁移为通用 PunchLoader Debug 模组。

## 隐藏颜色运行时预览

`1.10.0` 在 F8 面板中加入“隐藏颜色预览”，用于检查资源扫描发现的全部 14 个未登记材质。

- 使用“上一个/下一个”选择材质。
- “应用到玩家”把材质临时应用到当前玩家全部部件。
- “恢复原配色”逐部件恢复预览前材质。
- 不设置颜色收集状态，不修改存档，也不把材质加入颜色仓库。
- 切换场景会清除预览状态；卸载调试模组时会尝试恢复原配色。
- 面板同时显示材质的渲染类型和已知资源用途，便于判断能否进入内容解锁器白名单。

测试时重点观察透明度、纹理滚动、高光、不同部件 UV、受击闪烁、装备切换以及恢复后的外观。

仅用于 PunchLoader 汉化开发和验收，不随正式构建或正式部署安装。

## 热键

- `F8`：打开或关闭调试面板。
- `F9`：导出活动快照、完整会话和文本变化事件。
- `F10`：切换“仅显示疑似未翻译文本”。
- `F7`：隐藏调试面板并截取当前游戏画面。
- `F6`：隐藏面板并进入画面点选模式。

## 会话捕获

模组会持续记录活动 `TextMesh`，页面关闭或对象销毁后仍保留其最后状态。
每次 setter 原文和实际渲染文本发生变化时都会写入会话事件。

`F9` 会在游戏模组目录的 `captures` 文件夹生成：

- `active-时间.tsv`：导出时仍处于活动状态的对象。
- `session-时间.tsv`：本次游戏会话见过的全部对象。
- `events-时间.tsv`：setter 和渲染文本变化时间线。
- `scenes-时间.tsv`：已访问场景的构建索引、场景名、访问次数和最后访问时间。
- `reviews-时间.tsv`：人工复核状态、备注及更新时间。
- `unique-texts-时间.tsv`：按原文去重后的文本清单、出现次数、场景、路径和复核统计。
- `layout-issues-时间.tsv`：疑似尺寸无效、过小、未投影或超出父容器的活动文本。
- `dialogue-audit-时间.tsv`：全部对话原文、译文、运行时应用状态和问题原因。
- `summary-时间.txt`：可直接阅读的场景覆盖、未汉化、布局异常和复核进度摘要。

## 布局调试

选中对象后可以实时修改：

- `characterSize`
- `lineSpacing`
- 本地 X/Y 坐标
- 自定义预览文本

“Save layout preset”会把当前参数保存到 `layout-presets.tsv`。启用
“Auto presets”后，同一路径和原文的对象再次出现时会在 `LateUpdate()` 中自动应用，
便于跨页面或重进场景反复校准。

选中一条活动文本后，“高亮所选”会在游戏画面上用黄色边框标出它的实际渲染范围。
按 `F7` 或点击“截图(F7)”会隐藏调试面板，并把 PNG 保存到 `captures` 文件夹；
截图事件及其完整路径也会写入事件记录。

按 `F6` 或点击“点选文本(F6)”后，工具会用青色细框标出当前画面中的活动文本。
直接点击文字即可重新打开面板并选中对应 `TextMesh`；点击重叠区域时优先选择
渲染范围更小、更具体的文本。按 `Esc` 可以退出点选模式。

## 人工复核

选中文本后可以将其标记为“待处理”“验收通过”或“忽略”，并保存人工备注。
状态会持久化到 `review-status.tsv`，列表中的 `[未]`、`[待]`、`[验]`、`[略]`
分别表示未复核、待处理、验收通过和忽略。“只看未复核”会隐藏已通过和已忽略项目。
列表上方的“上一条”“下一条”可在当前筛选结果中循环检查文本。

## 布局异常检查

工具会检查活动文本的字符尺寸、行距、屏幕投影尺寸以及与最近父级渲染容器的关系。
疑似异常的列表项会显示 `[异常:原因]`；启用“只看布局异常”可以集中检查这些对象。
该检查用于缩小排查范围，“可能超出父容器”仍需结合黄色高亮和实际画面人工确认。

## 设置与长会话

筛选开关、步长、窗口位置和窗口尺寸会保存到 `debug-settings.tsv`。界面提供
“保存设置”和“恢复默认”按钮，退出模组时也会自动保存。

自检会在模组启动和每次完整导出前自动执行。“重新自检”按钮用于手动再次执行。
它会验证模组目录可写、场景列表和高亮资源是否可用，并汇总当前会话文本、
场景覆盖、布局预设和复核记录数量。持久化文件读取失败时不会阻止调试模组启动，
错误会显示在自检结果并写入游戏日志。

## 固定保留的英文名词

`untranslated-allowlist.txt` 每行保存一个确定不翻译的专有名词、角色名或按键文本。
“疑似未汉化”筛选会先剔除这些词，再检查剩余英文；因此 `Khotep 领主 Scarb` 不会
因为 `Khotep`、`Scarb` 被误报，但包含其他普通英文的句子仍会被拾取。修改文件后可
点击“重载名词”立即生效，无需重新编译模组。

每个捕获对象使用独立会话编号，不再直接把 Unity 实例编号当作历史记录编号；因此在
大量切换场景、Unity 重用实例编号时，旧场景文本不会被新对象覆盖。布局异常也会随历史
对象保留，最终导出可以覆盖整个调试会话，而不仅是当前场景。

## 背包状态触发器

当玩家的 `InventoryNaviScript` 已经处于活动状态时，面板顶部会显示
“Inventory state lab”，可调用游戏原有的 `SetState()` 切换：

- 轮盘主页面
- 装配零件
- 交换技能
- 分解零件
- 部件属性
- 关闭轮盘

工具不会伪造玩家、零件或技能上下文。“选择方向槽位”必须先通过正常装配流程
选择带技能的零件后进入，避免强制创建不完整状态。

为避免把两个互斥的轮盘子页面叠在一起，从“交换技能”“分解零件”或“部件属性”
切换到另一子页面前，必须先点击 `Main` 返回轮盘主页面。

## 场景触发器

`场景调试` 显示当前场景名称、构建索引和可用索引范围。输入目标索引后：

1. 点击 `准备加载场景`；
2. 在 5 秒内点击 `加载场景 #...`；
3. 加载后可点击 `上一个` 填回上一个场景索引，再次确认加载。

场景切换前后的索引会以 `scene-load` 和 `scene-enter` 事件写入会话记录。
工具会持续维护 `scene-catalog.tsv`，并提供“前一个未访问”和“后一个未访问”按钮，
方便逐一遍历构建中的全部场景。
直接按构建索引加载会绕过正常游戏流程，只用于定位场景中的文本；依赖存档、任务状态
或前置初始化的界面仍应通过正常玩法触发。

### 第五项场景验收

“第五项场景验收”提供关卡选择、锦标赛大厅、对战大厅、锦标赛结算和对战结算的
固定入口，对应已经确认的构建场景 `LevelSelect #24`、`TournamentLobby #38`、
`BattleLobby #23`、`TournamentCeremony #37` 和 `BattleCeremony #22`。首次进入时会
记住起始场景，“返回进入前场景”可以在这些验收场景之间切换后仍返回原处。

关卡选择场景可以直接用于文本采集和布局验收。大厅与结算场景依赖比赛状态；固定入口
目前用于确认静态预制体文本，后续再为其补充不会发奖励、不会写存档的临时参赛状态。

### 通关界面预览

在含有活动 `LevelScript` 的冒险关卡中，可在“通关界面预览”一行输入关卡编号 1–6，
然后点击“预览关卡结算”或“预览锦标赛结算”。该功能只复制并填充
`levelCompletePrefab`，不会击败 Boss、发放零件、推进关卡或写入存档；点击“关闭预览”
即可返回。它用于验收结算标题、结果正文、奖励标签和确认按钮的汉化样式。

### 临时状态提示触发器

“状态提示测试”提供“已获得配色”和“+ 1 条命”两个按钮。工具会复用游戏原有的
`IndicatorScript` / `BitsIndicatorScript` 预制体显示提示，但不会实际收集配色、增加生命、
修改 Bits 或写入存档。提示会按游戏原本的持续时间自动消失。

### 已有译文的运行时菜单验收

“菜单运行时验收”可直接预览暂停菜单、游戏结束、对战设置、对战结算、新游戏确认和
默认手柄确认界面。预览复用 `GUIDataScript` 中的原始菜单预制体；对战结算使用相同的
`GUILayoutMenuScript` 布局填充 `rematch / to lobby / quit`。工具会持续冻结预览菜单的
操作，因此方向键、确认键和鼠标不会执行删除进度、切换场景或修改设置等原始动作。
点击“关闭验收界面”即可销毁预览。

## 自动巡检

“自动巡检”可以依次加载构建列表中的全部场景，等待场景稳定后捕获活动文本，自动记录
疑似未汉化项和布局异常。启用“同时巡检背包页面”后，整个巡检任务只会在首次找到
活动背包控制器时执行一次“主页面 → 装配 → 主页面 → 技能 → 主页面 → 分解 →
主页面 → 属性 → 主页面”的采集，并在离开场景前恢复原状态。后续场景不会重复巡检
结构固定的背包界面，避免背包文本淹没场景文本。

为避免误触，开始全场景巡检需要在五秒内完成“准备”和“确认”两步。巡检结束后会
自动执行完整导出并返回启动巡检时所在的场景；运行中也可以点击“停止并导出”。
每步等待时间可在界面中设置。依赖任务进度、存档内容或玩家主动选择目标的深层页面，
仍会在正常游玩触发时由会话捕获器持续记录。

自动巡检开始时还会直接读取 `ChineseLocalization/data/dialogue.tsv`，并通过
`GameHandler.dialogData` 检查全部对话行，无需在地图中逐个寻找 NPC 或手动触发约
400 行对话。巡检会区分“已应用”“仍为原文”“保留原文”“运行时未找到”，同时检查
空译文、原译文相同以及未列入保留名词表的英文。结果会显示在面板并单独导出为
`dialogue-audit-时间.tsv`。如果启动时游戏对话数据尚未初始化，工具会在后续场景继续
尝试，完整导出前也会再检查一次。

### 真实对话渲染巡检

数据巡检只能确认译文是否进入运行时，不能证明文字在实际对话框中没有溢出。点击
“等待并绑定对话框”后，关闭调试面板并在游戏中正常触发任意一段对话。工具会复制
当时真正使用的 `TextBoxScript` 对话框，保留它的字体、材质、层级、位置、缩放和背景
框，然后把全部译文逐行放进这个副本进行真实渲染。

巡检会记录每行文字和背景框的屏幕矩形、字体、字符尺寸、行距及溢出像素，并输出
`dialogue-render-audit-时间.tsv`。发生溢出、未投影或渲染尺寸异常时会自动截图；勾选
“每行截图”可以保存全部约 400 张效果图。巡检完成或手动停止后会销毁测试副本并恢复
原对话框，不会修改游戏对话数据。

## 构建与部署

```powershell
.\scripts\build_debug.ps1
.\scripts\deploy_debug.ps1 -GameDir 'F:\Codex\MBP_PROJ\ModdedGame'
```

正式的 `build_all.ps1` 和 `deploy.ps1` 均不会处理该模组。
